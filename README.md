# AthenaSummary – Brush-up Rules

The rules for turning a writer's draft into a finished, sellable
AthenaSummary. People and AI assistants (Claude) both use them. The goal is a
student-focused summary with **no signs of AI** and complete consistency in
writing, visuals and formatting.

## Using Claude

1. Start a Claude Code session on this repository.
2. Upload the writer's draft (.docx).
3. Send this prompt:

```text
Brush up the attached summary. Follow README.md and every file it lists,
in its priority order. Ask me first if you need course material
(syllabus, old exams). Send back only the finished .docx.
```

> [!NOTE]
> Claude starts every new session blank. It knows these rules only because
> they are in this repository, so update this README whenever a rule changes.

## 1. Output and file naming

- The editor (or Claude) has **full autonomy** to edit the draft.
- **Deliver only the finished .docx.** No tracked changes, no Word comments,
  no findings table, no grade.
- Don't start until the summary lead asks.
- Ask for the syllabus or old exams only when they are really needed.
- **File name:** `<UNI>-<PROG>-<SKU>-2627-<week number>.docx`, no stage word.
  - The SKU is in the summary or in the draft's file name.
  - Example: `RU-PSY-1033-2627-4.docx`

## 2. Week structure

**Week 1 file:** title page, then the week. No table of contents and no Exam
Analysis page.

**Every other week file:** starts directly with the week title.

**Page numbers start at 1** in every file.

Every week follows this order:

```text
┌──────────────────────────────────────────────┐
│ Week 4 – Short General Title      (Heading 1) │
├──────────────────────────────────────────────┤
│ WHITE BOX                                     │
│ Week 4:                                       │
│ Standard intro sentence                       │
│ After studying this week, I know:             │
│ ☐ topic   ☐ topic   ☐ topic     [pie chart]   │
├──────────────────────────────────────────────┤
│ GREY BOX                                      │
│ **Hook Question**                             │
│ Question + answer options (not answered yet)  │
├──────────────────────────────────────────────┤
│ Content: lectures, chapters, boxes            │
├──────────────────────────────────────────────┤
│ GREY BOX (end of week)                        │
│ The hook question again                       │
│ Correct answer + why it is correct            │
│ Short reason why the other options are wrong  │
└──────────────────────────────────────────────┘
```

- If the draft has no week title, write one: short and general.
- The first line of the hook box is `Hook Question` in **bold**. It replaces
  labels such as "Use this question to test your knowledge!".
- The answer options are in the same order at the start and the end.
- **No checklist and no pie chart at the end of the week.**
- **No placeholders** such as "N" or "X" left in the document.
- Pie chart percentages: leave them as given.

## 3. Headings

| Draft has | Lecture | Chapter | Section | Sub-section |
|---|---|---|---|---|
| Lecture + chapter | Heading 2 | Heading 3 | Heading 4 | Bold text |
| Chapter only | – | Heading 2 | Heading 3 | Heading 4 |

- Always use Word's heading styles, never bold text that only looks like a
  heading.
- Format: label, space, en dash, space, title: `Week 4 – Title`,
  `Lecture 7 – Title`, `Chapter 9 – Title`.
- Section numbers: `9.1 Title`, following the book. Numbers never repeat or
  go backwards.

| Level | Font |
|---|---|
| Heading 1 | Calibri 16 bold, starts a new page |
| Heading 2 | Calibri 14 bold |
| Heading 3 | Calibri 12 bold |
| Heading 4 | Calibri 11 bold |

## 4. Layout and formatting

**Page and text**
- A4, margins 2.5 cm.
- Body text: Calibri 11, justified, single line spacing.

**Header and footer**
- Logo, header and footer come from the gold examples.
- The logo alternates: **odd pages right, even pages left**.
- The header shows the current week title. It is the same on every page.
- Footer: a line with the page number in the middle.

**Spacing**
- Spacing comes from paragraph settings. **No empty lines and no manual page
  breaks.**

**Nothing breaks in an ugly place**
- No paragraph, bullet point or table row splits across two pages.
- A heading never sits alone at the bottom of a page.
- Lists of up to 6 items stay on one page.

**Lists**
- Use real Word lists: `•` → `o` → `▪`, or `1.` → `a.` → `i.`
- Use them only where they help: steps, enumerations, definitions.

**Emphasis**
- **Bold** key terms in every paragraph ("**Term:** definition").
- *Italics* to stress a word in a sentence.
- No underlining.

## 5. Writing

**Language**
- English summaries use **UK spelling**: behaviour, labour, organisation,
  favourable.

**Spelling**
- Fix spelling and typos directly.

**Body text is neutral**
- No "you" or "we".
- No sentences that start with "There", "It" or "Therefore".

**Boxes, the hook and the week box are student-friendly**
- They may speak to the student as "you".

**No signs of AI.** Read every page as a sceptical student looking for AI.
- ❌ No long dash (—). The en dash (–) appears in headings only.
- ❌ No linking phrases between paragraphs: "Furthermore", "Moreover",
  "Interestingly", "As discussed in the previous chapter".
- ❌ No references to the source in the text: no page numbers, no "The
  chapter emphasises…", no "The author argues…".
- ❌ No over-explaining.
- ✅ Keep theory and concept names and the people behind them, plus dates
  already in the draft, e.g. *Meyer, Allen and Smith (1993)*.

**Paragraphs**
- At least **4 lines**. The maximum depends on what flows best.
- Paragraphs may be rewritten, split or combined.

**Cutting**
- Remove repeated content and tighten the wording.
- **Never remove a topic** that is not covered elsewhere.

## 6. Boxes and examples

A box is a **one-cell table**:
- full text width
- thin black border
- bold label on its own first line
- black icon in the top-right corner

No floating text boxes.

| Box | Label | Fill | Purpose |
|---|---|---|---|
| Example | `Example:` / `Examples:` | Grey D0CECE | A real-world case for a tricky term |
| Tip | `Tip!` | White | What to focus on for the exam, key differences |
| Please note | `Please note!` | White | Hard topics and common mistakes |
| Stop and think | `Stop and think!` | White | A question to test understanding |
| Mnemonic | `Mnemonic:` | White | A memory trick, rhyme or acronym |
| Hook | `Hook Question` | Grey | The weekly exam question |

**Label clean-up**

| Draft label | Becomes |
|---|---|
| Exam tip! / Important exam tips: / Key idea: / Important distinction: | `Tip!` |
| Memory trick: | `Mnemonic:` |
| Example exam question: | `Stop and think!` or a plain white box, whichever fits the flow |

**How many**
- Aim for **2+ boxes per page**, using all 5 types.

**Names in examples**
- Use team names: **Adrian, Xavier, Matko, Thisaru, Amber, Elisa**.
- Replace other names in the draft with these.
- **Use no pronouns for them.** Repeat the name or rephrase.

**Mnemonics**
- Make the first letters **purple and bold** (`7A4E8C`).

**Icons**
- Take them from the gold examples.
- If one is missing, use the closest matching black silhouette.

## 7. Visuals and tables

- **Remake every diagram** in the purple Athena palette. Images are fine;
  editable SmartArt is not required.
- Images are centred and in line with the text: at most 16 cm wide and 12 cm
  high.
- Data tables use the purple style:

| Part | Style |
|---|---|
| Header row | Fill `AA7FB8`, bold |
| Body rows | Banding `DDBDFD` on every other row |
| First column | Purple bold `7A4E8C` (short terms only) |
| Size | AutoFit to contents, centred |

**Colour reference**

| Use | Hex |
|---|---|
| Table header | `AA7FB8` |
| Table banding | `DDBDFD` |
| Purple text | `7A4E8C` |
| Grey box fill | `D0CECE` |

## Final check

Scroll through every page before sending:

- [ ] File name: `<UNI>-<PROG>-<SKU>-2627-<week>.docx`
- [ ] Week title → white week box → grey Hook Question → content → grey answer box
- [ ] No checklist or pie chart at the end of the week; no "N" or "X" placeholders
- [ ] Headings use Word styles, with en dashes and correct numbering
- [ ] UK spelling, no typos
- [ ] No long dashes, no linking phrases, no source references, no over-explaining
- [ ] Neutral body text; "you" only in boxes
- [ ] Key terms in bold
- [ ] 2+ boxes per page, all 5 types, team names without pronouns
- [ ] All diagrams in purple; tables in the purple style
- [ ] Logo alternates; header and footer the same on every page
- [ ] Page numbers start at 1
- [ ] No empty lines; nothing breaks across a page in an ugly place
